MVC Architecture Overview

MVC stands for Model–View–Controller. It is a software design pattern used in web and application development to organize code into three separate parts.

Main Purposes
  • Separate concerns (logic, UI, and control)
  • Make systems easier to manage, update, and scale
  • Improve teamwork in development

Structure of MVC

Model (The Data Authority)

The Model is responsible for managing data, handling business logic, and communicating with the database.

Key Functions:
  • Stores and retrieves data
  • Processes data (e.g., calculations, rules)
  • Updates the database when needed
Example: Handling student records (name, ID, grades) in a student system.
View (The User Interface)

The View is the User Interface (UI)—what the user sees on the screen.

Key Functions:
  • Displays data from the Model
  • Sends user input to the Controller
  • Does not handle logic or data processing
Example: Webpages showing student information, forms, and dashboards.
Controller (The Middleman)

The Controller acts as the middleman between the Model and the View.

Key Functions:
  • Receives user input from the View
  • Processes requests
  • Calls the Model to update/retrieve data
  • Sends updated data back to the View
Example: Getting input, sending to Model, and updating View when a user clicks "Submit".

Flow of MVC in a Web Application

Step-by-step interaction:

User Interaction (Client Side): User performs an action on the interface (e.g., clicking a button or submitting a form).
Controller Receives Request: Handles user input and interprets what action to take.
Controller Communicates with Model: Sends request to process data (e.g., check login credentials).
Model Processes Data: Interacts with database, retrieves, updates, or validates data.
Model Returns Data to Controller: Sends processed result (e.g., valid or invalid login) back.
Controller Sends Data to View: Selects appropriate View and passes data.
View Displays Output to User: Presents final output (e.g., dashboard or error message).

Application in Real Projects

Example: Login System Flow
  1. User enters username and password in the login page.
  2. The request is sent to the Controller.
  3. The Controller validates input format (basic validation).
  4. The Controller calls the Model to verify credentials from the database.
  5. The Model checks if the user exists and if the password matches.
  6. The Model returns the result to the Controller.
  7. The Controller decides: If valid → redirect to dashboard; If invalid → return error message.
  8. The View displays the result (success or error).

Introduction to API

API stands for Application Programming Interface. IAPI stands for Application Programming Interface. It is a set of rules that allows different software applications to communicate with each other. APIs act as a bridge between the frontend and backend, enabling systems to exchange data and functionality efficiently. In modern software development, APIs are essential for connecting mobile apps, websites, databases, and third-party services.

  • Connects different software applications
  • Acts as a bridge between frontend and backend
  • Enables data sharing between systems
  • Used in web apps, mobile apps, and cloud services
  • Important for modern software development

Planning the API

Purpose of the API
  • Handle client requests and return appropriate responses
  • Manage data flow between the user interface and the database
  • Enforce business logic (via Controllers and Models in MVC)
  • Provide secure and structured access to system features
Target Users

Web applications (admin dashboards, browser-based systems) and Mobile applications (Android/iOS apps).

Example Features
FeatureFunctionMVC Role
Login Authenticates users using email/username and password. Returns a token. Controller validates request; Model checks credentials in database.
Fetch data Retrieves data from the database. Supports filtering, sorting, and pagination. Controller handles parameters; Model fetches data.
Submit data Accepts user input (forms, uploads, etc.) and stores in database. Controller validates input; Model saves data.

API Design

This section outlines how the frontend communicates with the backend using Endpoints and JSON.

1. API Endpoints Table
MethodEndpointDescriptionMVC Role
POST/api/loginAuthenticates user credentialsController validates, Model verifies
GET/api/studentsFetches a list of all studentsModel retrieves records from DB
GET/api/students/:idFetches details of a specific studentController passes ID to Model
POST/api/studentsAdds a new student recordModel saves data to DB
PUT/api/students/:idUpdates an existing studentModel modifies specific record
DELETE/api/students/:idRemoves a student recordModel deletes record from DB
2. Request & Response Structure

APIs use JSON (JavaScript Object Notation). It is lightweight and easy for both layers to read.

A. Request Example (The "Input")
{ "username": "Cejay_Pantas", "password": "securePassword123" }
B. Response Example (The "Output")
// Success Response (200 OK) { "status": "success", "message": "Login successful", "data": { "user_id": 101, "role": "Student", "token": "eyJhbGciOiJIUzI1..." } } // Error Response (401 Unauthorized) { "status": "error", "message": "Invalid username or password" }
3. Design Principles
  • Statelessness: Every request contains all information needed (no stored session on server).
  • Standard HTTP Methods: GET (Read), POST (Create), PUT (Update), DELETE (Delete).
  • JSON Format: Ensuring high compatibility between Backend and apps.
